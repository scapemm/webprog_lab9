HOW	IT	WORKS
1.	
WHERE	STATE	LIVES.
	
_lines
	is	owned	by	the	
State
	object,	which	Flutter	keeps	alive	as	long	as	the	widget	stays	in	the	tree.	Pop	the	page

2.	
HOW	IT	MUTATES.
	
setState
	does	two	things:	runs	the	closure,	then	marks	this	element

	so

	runs	on	the	next	frame.	Reassigning

	to	a	new	list	is	not	required	by

WHERE	STATE	LIVES.
	In	the	
ProviderContainer
	owned	by	the	root

}

HOW	IT	WORKS
1.	
EVENTS	ARE	DATA.
	Each	user	intention	is	an	immutable	object.	Because	
CartEvent
	is	sealed,	you	can	
switch
	over	events	exhaustively
elsewhere	(logging,	analytics)	and	the	compiler	tells	you	when	a	new	event	is	unhandled.
2.	
HANDLERS.
	
on<E>(handler)
	registers	a	handler	per	event	type;	the	
emit
	you	receive	is	scoped	to	that	handler	and	may	be	called	many	times

sequentially	by	default

	to	change	that	(concurrent,	droppable,

THE	UI	ADDS,	NEVER	CALLS.
